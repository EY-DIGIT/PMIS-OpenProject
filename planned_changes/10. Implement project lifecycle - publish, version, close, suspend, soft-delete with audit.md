# Feature: Project Lifecycle — publish, version, close, suspend, soft-delete + audit

## What changed

Extended the `projects` module with a full state machine, versioning, soft-delete, and an audit trail. The goal: published projects become immutable baselines, edits happen on cloned "versions", admins drive state transitions, and deletions are recoverable.

### Status lifecycle

New lowercase vocabulary in DB (replaces the old `new / in_progress / completed / on_hold`):

```
new ──► draft ──► published ──► closed
  │        │          │            ▲
  │        └──► closed ◄────────────┤
  └──────► closed                   │
                                    │
  (versions only) ── suspended ─────┘ (terminal; no reactivation)
```

- `new → draft`: triggered by the M/A/T/S "Save Project" button once at least one milestone exists. Exposed as `transition_to_draft_if_new(db, project_id, actor_id)` so the milestones contributor's save endpoint can call it.
- `→ published`: admin-only. `POST /api/v3/projects/{id}/publish`.
- `→ closed`: admin-only, allowed from any non-closed state. `POST /api/v3/projects/{id}/close` (optional `{reason}` body).
- `→ suspended`: version rows only. Terminal — a new version must be cloned from the baseline instead of reactivating.

Illegal transitions return HTTP 409 with `{errorIdentifier: "invalid_transition", from, to}`.

### Versioning

- `POST /api/v3/projects/{identifier}/versions` clones a **published baseline** into a new row with `is_version=true`, `status='new'`, `version_of=source.id`, `baseline_id=source.id`, `version_no=next`, identifier `{source.identifier}-v{n}`.
- One-active-version-per-baseline enforced two ways:
  - Service layer: `ProjectRepository.active_version_exists(baseline_id)` → 409 `active_version_exists` on collision.
  - DB layer: partial unique index `ux_projects_active_version_per_baseline` on `version_of` with `WHERE is_version=1 AND status != 'suspended' AND deleted_at IS NULL`.
- Versions of versions are forbidden (source must have `is_version=false`).
- Inside the version-create transaction, we call `clone_tree_for_version(db, source_id, target_id)` — the deep-clone owned by the M/A/T/S contributor. Stub lands a logging no-op today so the branch stays runnable; replaced upstream.

### Soft-delete + cascade

- `DELETE /api/v3/projects/{id}` is now a **soft delete**: stamps `deleted_at` and `deleted_by`, calls `cascade_soft_delete_project(db, project_id, actor_id)` (M/A/T/S contributor's cascade; stubbed), commits atomically.
- All project reads (`get_by_id`, `get_by_identifier`, `list_*`) filter `deleted_at IS NULL` by default; an `include_deleted` flag is exposed on the repository for admin-only flows.
- Identifier uniqueness deliberately ignores `deleted_at` — a soft-deleted row still reserves its identifier so history can be reconstructed.
- No `assert_project_editable` call on delete: admin-only permission is the gate, and deletion is available even on published baselines (matches the UI mockup; soft-delete keeps data recoverable).

### Editable-field whitelist

Single source of truth in `app/api/v3/projects/services/transitions.py`. The set returned by `editable_fields_for(project)` depends on the project's state:

| State | Editable via PATCH |
|---|---|
| Non-version, status ∈ {`new`, `draft`, `closed`, `suspended`} | `name, description, owner, start_date, end_date, public, active, status_explanation` |
| Non-version, `status='published'` | ∅ (locked) |
| Version (any status) | `owner, public, actual_end_date, status_explanation` |

`status` is **never** in the whitelist — status changes go through `/publish`, `/close`, `/suspend`. `category`, `identifier`, versioning fields, and audit fields are never editable. Unknown fields in a PATCH return 422 `invalid_field` with a `rejected` list in the error payload.

### Cross-team integration points (from Phase 2 collision map)

1. **`projects.deleted_at`** — column owned here, used by the M/A/T/S cascade JOINs.
2. **`assert_project_editable(db, project_id)`** at `app/core/project_lock.py` — enforces the published-baseline lock. Called from `update_project`. Raises `ValidationError` with `errorIdentifier='project_locked'`. M/A/T/S contributor is expected to extend this function to cover subtree-level write paths; signature preserved.
3. **`clone_tree_for_version(db, source_id, target_id)`** — hook invoked inside `create_version`'s transaction after the target row flushes.
4. **`cascade_soft_delete_project(db, project_id, deleted_by)`** — hook invoked inside `delete_project`'s transaction before commit.

### Audit trail

New `project_audit_logs` table `{id, project_id, actor_id, action, before, after, created_at}`. Actions recorded: `project.create`, `project.update`, `project.publish`, `project.close`, `project.suspend`, `project.version.create`, `project.soft_delete`. Before/after payloads are JSON snapshots of the project fields that mutate. Audit rows live inside the same transaction as the change they describe. No read endpoint yet — table is populated so history isn't lost; viewer added in a later PR.

## Design decisions & constraints

- **Repository commit boundary moved to service edge.** `ProjectRepository.create/update/soft_delete/hard_delete` now `flush()` only; services commit once per operation. This was required to make the version-create and delete-cascade transactions atomic (project row + subtree changes in one tx). Existing callers updated in the same PR.
- **Identifier generation hybrid.** Server auto-generates `prj{n:03d}` when the client omits `identifier` on POST; version identifiers are always server-generated as `{baseline}-v{n}`. This preserves backward compatibility with tests/scripts that supplied identifiers while aligning with the spec's intent to make versioning system-controlled.
- **No Alembic introduced.** This codebase relies on `Base.metadata.create_all` plus ad-hoc `ALTER TABLE` drift handlers in `session.py`. Introducing Alembic would have required baselining every existing table, larger in scope than this feature. New columns + the partial unique index are added via the same PRAGMA-guarded idempotent pattern. Flagged as tech-debt.
- **Admin-only transitions enforced at the route via RBAC.** New permissions `PROJECTS_PUBLISH` and `PROJECTS_CLOSE` mapped to the `ADMIN` role only. Transitions service additionally double-checks `actor_is_admin` so the service is safe to call outside HTTP.
- **Date-in-future validator retained.** Existing behavior preserved — start/end dates must be in the future on submit. Does not apply to `actual_end_date` (which records a past completion on versions).
- **Suspended = terminal.** Simplifies the active-version invariant: the partial unique index treats anything non-suspended as active. Reactivation would re-collide with concurrent new versions; instead the workflow is "suspend this version, create a new one from the baseline."
- **`category` is immutable after create.** Matches the UI mockup (disabled in edit mode). Not in any editable whitelist.
- **Soft-deleted rows keep their identifier locked.** Prevents reuse and preserves audit linkage.
- **Stubs for cross-team dependencies** (`project_lock` is fully implemented for project-row scope; `clone_tree_for_version` and `cascade_soft_delete_project` are logging no-ops) so the branch is runnable. Upstream replacement must preserve signatures and error types.

## Endpoints

| Method | Path | Perm | Notes |
|---|---|---|---|
| POST | `/api/v3/projects` | `PROJECTS_CREATE` | `identifier` optional; server generates `prj{n:03d}` if omitted |
| GET | `/api/v3/projects` | `PROJECTS_READ` | filters soft-deleted rows |
| GET | `/api/v3/projects/{project_id}` | `PROJECTS_READ` | 404 if soft-deleted |
| PATCH | `/api/v3/projects/{project_id}` | `PROJECTS_UPDATE` | calls `assert_project_editable`; whitelist enforced |
| DELETE | `/api/v3/projects/{project_id}` | `PROJECTS_DELETE_ALL` (admin) | soft delete + cascade |
| POST | `/api/v3/projects/{project_id}/publish` | `PROJECTS_PUBLISH` (admin) | transition to `published` |
| POST | `/api/v3/projects/{project_id}/close` | `PROJECTS_CLOSE` (admin) | optional `{reason}` body |
| POST | `/api/v3/projects/{project_id}/suspend` | `PROJECTS_UPDATE` | versions only |
| POST | `/api/v3/projects/{identifier}/versions` | `PROJECTS_CREATE` | clones published baseline |
