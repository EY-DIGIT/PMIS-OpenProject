# Doc 33 — Versioning removal, vendor role, RBAC extension, notifications

This doc covers three independently-shippable changes scoped together
because the user requested them as one work item:

1. **Versioning removal** — drop the entire baseline/version split.
   Projects are the single source of truth.
2. **RBAC extension** — runtime permission registration, module
   taxonomy, artifact cleanup.
3. **Notification-driven 2FA + forgot-password** — new microservice
   client, OTP login flow, self-service password reset.

Each ships as its own commit. **Status as of this doc snapshot:**
change 1 is implemented and tested. Changes 2 and 3 follow in
subsequent commits.

The commit boundary keeps blast-radius narrow per feature. If anything
goes wrong with notifications, it doesn't affect the versioning
removal that's already live.

## Decision log (from the Q&A round)

All scope decisions taken before implementation began:

| Q | Decision | Rationale |
|---|---|---|
| 1.1 | Drop existing version rows in any deployed DB. | User explicitly said versioning is no longer needed; preserving them with no propagation infrastructure would just leak. |

| 1.6 | Vendor access via a new global `vendor` RBAC role rather than per-project membership tier. | User said "use the permissions model to create a vendor role". |
| 1.7 | Audit expansion: T/S create + delete + dep changes captured on `project_audit_logs`; new `actor_role` column. | Mirror what was already captured for M/A. |

| 2.2 | RBAC artifact sweep: remove `Role` enum, `ROLE_PERMISSIONS` dict, `has_permission`, `get_role_permissions`. Keep `Permission` enum (transitional). | Per the audit. |
| 2.3 | Keep `admin` role lockout. User-created roles have no lockout. | Same protection as today. |
| 3a.1-6 | OTP table + single-use codes + two-stage login + per-user opt-out (default-mandatory) + env-var cooldown/TTL/max-attempts + per-login channel selection. | Standard 2FA flow. |

| 4 | All in one planned_changes doc. | This file. |
| 5 | Order: 1 → 2 → 3 (deepest → smallest). | Reduces churn. |

## Change 1 — Versioning removal + audit expansion + vendor role

### Schema changes

**Dropped from `projects` table:**
- `is_version BOOLEAN`, `version_of VARCHAR(36)`, `baseline_id VARCHAR(36)`, `version_no INTEGER`.
- Indexes `idx_projects_is_version`, `idx_projects_version_of`, `idx_projects_baseline_id`.
- Partial unique index `ux_projects_active_version_per_baseline`.

**Dropped from other tables:**
- `milestones.cloned_from_id` + index.
- `activities.cloned_from_id` + index.
- `project_status_transitions.version_only`.

**Added to `project_audit_logs`:**
- `actor_role VARCHAR(50) NULL` — audit row records the role bucket the
  actor occupied at the time of the change (`admin` / `member` /
  `vendor` / `viewer`). Indexed.
- New index `idx_project_audit_logs_action` for the expanded action
  query path (T/S subtree audit rows).

**Migration:** [alembic/versions/d5e6f7a8b9c1_doc33_drop_versioning.py](../alembic/versions/d5e6f7a8b9c1_doc33_drop_versioning.py).
Wipes any version rows + suspended-status rows BEFORE dropping the
columns that filter for them. Down-revision is structural only —
deleted rows are not restored.

### Vendor role (Q1.6)

Seeded as a 4th built-in role alongside `admin` / `member` / `viewer`
in [rbac_repository.py:sync_builtin_permissions](../app/infrastructure/db/repositories/rbac_repository.py).

`VENDOR_ROLE_PERMISSIONS` in [app/core/permissions.py](../app/core/permissions.py)
is curated subset of `MEMBER_ROLE_PERMISSIONS`:

**Included:**
- `users:read`, `users:update` (own profile)
- `projects:read`, `projects:update` (read + edit project content)
- `vendors:read`, `resource_types:read`, `master_data:view` (read-only catalog)
- `project_members:read`, `meetings:view`
- `milestones:create/read/update/delete`
- `activities:create/read/update/delete`
- `tasks:create/read/update/delete`
- `subtasks:create/read/update/delete`
- `comments:create/read/delete`
- `attachments:create/download/delete`

**Excluded** (admin/member-only):
- `projects:create/publish/close/delete*` — lifecycle is admin-only.
- `users:read_all`, `users:*_all` — vendors only see themselves.
- `rbac:assign`, `roles:*`, `permissions:*` — RBAC is admin-only.
- `master_data:manage` — catalog edits are admin-only.
- `work_packages:*` — admin/member-tier module.
- `meetings:create/update/delete` — admin/member drive meetings.

## Change 3 — Notifications + 2FA + forgot-password (TBD in next commit)

Deferred to a separate commit per Q5 + Q6. Will cover:

- New `notification_log` table.
- `NotificationClient` abstract + `MockNotificationClient` (writes to
  `notification_log` for inspection) + `HttpNotificationClient` stub
  pointing at the in-flight microservice.
- New `otp_codes` table with hashed codes, `expires_at`,
  `consumed_at`, `attempt_count`.
- Two-stage login flow:
  - `POST /users/login` returns `{requires_otp, ephemeral_token,
    channels_available}` when 2FA is required for the user.
  - `POST /users/login/send-otp` triggers the send.
  - `POST /users/login/verify-otp` mints the real JWT.
- Per-user `users.two_factor_enabled` (default True per Q3a.4 —
  mandatory by default with admin override).
- Env vars: `OTP_TTL_SECONDS`, `OTP_RESEND_COOLDOWN_SECONDS`,
  `OTP_MAX_ATTEMPTS`, `OTP_CODE_LENGTH`, `REQUIRE_2FA` (global force-on
  override), `PASSWORD_RESET_TTL_SECONDS`.
- New `password_reset_tokens` table (hashed token, channel, TTL).
- Endpoints `POST /users/forgot-password` (anti-enumeration: always 200)
  and `POST /users/reset-password`.
