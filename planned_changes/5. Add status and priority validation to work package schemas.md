# Fix: Missing enum validation for work package status and priority

## What will change
Add field validators for `status` and `priority` in work package schemas, similar to how project schemas validate status and category.

## Why
Currently `status` and `priority` accept any string value. The domain model expects specific values (status: new/in_progress/resolved/closed/on_hold; priority: low/normal/high/urgent) but validation only happens at documentation level, not at the schema level. Invalid values pass through to the database.

## Files affected
- `app/api/v3/work_packages/schemas.py`: Add `@field_validator` for status and priority with allowed value lists

## Severity: MEDIUM
