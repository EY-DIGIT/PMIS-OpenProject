# Fix: Timezone-naive datetime comparison in project date validators

## What will change
Add timezone awareness handling in project schema date validators to handle clients sending naive (no timezone) datetimes.

## Why
The validator compares input datetimes with `datetime.now(timezone.utc)` (timezone-aware). If a client sends a naive datetime (e.g., `"2026-05-01T00:00:00"` without `Z` or offset), comparing aware vs naive datetimes raises a `TypeError` in Python. The validator should normalize input to UTC if no timezone is specified.

## Files affected
- `app/api/v3/projects/schemas.py`: Update `validate_dates_in_future` validators in both `ProjectCreateRequest` and `ProjectUpdateRequest`
